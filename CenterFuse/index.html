CenterFuse

The umbrella experience and shared architecture for two independent products: SellFuse for sellers and BuyFuse for buyers.

FamilyCenterFuse → SellFuse + BuyFuse
StackTypeScript and Node.js

Commercial roleUmbrella, not a paid SKU

Role

Shared identity and navigation without a source-code monolith.

CenterFuse contains the parent site, product-family configuration and design primitives, plus the additive PostgreSQL migration that establishes explicit schema ownership. SellFuse and BuyFuse build, test, deploy, and evolve in separate repositories.

Architecture

Product-family cohesion with independent runtime boundaries.

The current code supports the umbrella relationship shown here. CenterFuse is best presented as organizational and shared platform infrastructure, not as a finished customer SaaS or a separate membership purchase.

  1. CenterFuse owns the parent experience and cross-product schema foundation.
  2. SellFuse owns seller, listing, marketplace, and inference workflows.
  3. BuyFuse owns buyer research and purchase-status workflows.
  4. Configured URLs connect separately deployed products without filesystem imports.

Current status

Portfolio-ready platform architecture.

Implemented

Parent site, shared configuration and UI primitives, additive migration validation, container configuration, CI, and liveness endpoint.

Not a membership product

Customer billing belongs in the products that deliver customer value, not the umbrella brand.

Production gap

Shared production identity, durable data, deployed product URLs, observability, and operating procedures remain future work.
