GodModeAI

A local-first AI coding and computer-agent environment that puts one observable, permission-aware agent engine behind terminal, authenticated web, and Windows desktop interfaces.

BackendPython and FastAPI
InterfacesTerminal, web, WinForms and WebView2
InferenceLocal Ollama or protected remote HTTPS
QualityAutomated tests, CI, containers and rollback

Problem

Useful agent automation needs boundaries operators can see and control.

GodModeAI explores how a coding agent can work across local and hosted environments without treating unrestricted tool access as a default. The project centers explicit capabilities, project isolation, observable execution, secure inference routing, and recoverable changes.

Architecture

One backend, multiple clients, two inference paths.

A shared FastAPI service exposes authenticated APIs for the terminal, browser UI, and native Windows client. Local projects stay on the workstation through an outbound, project-scoped Local Bridge; remote projects run in isolated authorized workspaces.

  1. Clients submit work through the terminal, authenticated web UI, or WinForms/WebView2 desktop application.
  2. Agent engine applies Ask, Plan, Edit, Autonomous Run, or Coding Team behavior with capability evaluation and structured operational events.
  3. Inference router selects local Ollama or an authenticated remote gateway according to the configured routing and fallback policy.
  4. Safety services contain workspace access, redact secrets, record audit evidence, and create checkpoints before approved mutation.

Engineering decisions

Designed for observable and recoverable operation.

Permission-aware modes

Read-only modes cannot mutate. Edit and autonomous modes construct a plan, request scoped approval, create a checkpoint, and preserve rollback information.

Workspace safeguards

Path containment, traversal protection, executable allowlisting, no-shell subprocesses, timeouts, output limits, Git safeguards, and secret redaction constrain local tool execution.

Operational visibility

Ordered task and tool events, audit records, persistent memory, health reporting, and provider status make execution traceable across interfaces.

Deployable persistence

SQLite supports local use, while hosted configuration accepts PostgreSQL-compatible storage. Docker and GitHub Actions cover container and test workflows.
